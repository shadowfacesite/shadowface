# Тёмный вход

Статичный сайт-вход. Логин и пароль нигде не хранятся — они работают
только как ключ шифрования. Содержимое закрытого экрана лежит в файле
зашифрованным (AES-256-GCM, ключ через PBKDF2, 600 000 итераций).

## Как это защищено

При сборке GitHub Actions берёт логин и пароль из секретов, шифрует ими
содержимое закрытого экрана и кладёт в страницу **только шифроблок**.
Ни логина, ни пароля, ни самого содержимого в опубликованном файле нет.

Открыть закрытый экран, не зная пароль, нельзя: расшифровывать нечем.
Отключить проверку в коде тоже бесполезно — расшифрованного текста
просто не существует, пока не введён верный пароль.

## Секреты

Settings → Secrets and variables → Actions → New repository secret

| Имя | Обязателен | Что это |
|---|---|---|
| `SITE_LOGIN` | да | Логин |
| `SITE_PASSWORD` | да | Пароль |
| `VAULT_HTML` | нет | Вся закрытая страница целиком (шифруется) |
| `VAULT_VIDEO` | нет | Ссылка YouTube на экран **после** входа (шифруется) |
| `VAULT_TEXT` | нет | Текст на экран **после** входа (шифруется) |
| `RECOVERY_VIDEO` | нет | Ссылка YouTube на экран «Забыли логин и пароль?» |

Ссылки годятся в любом виде: `watch?v=`, `youtu.be/`, `shorts/`, `embed/`.

## Закрытая страница отдельным файлом

Запусти `python build.py` — при первом запуске он сам создаст `vault.html`
из образца. Дальше правь этот файл как обычную страницу.

`vault.html` — единственный файл, который **нельзя загружать на GitHub**:
репозиторий на бесплатном тарифе открыт всем, и содержимое закрытой
страницы прочитали бы прямо там, без всякого пароля. Он занесён в
`.gitignore`, но при загрузке файлов через сайт GitHub мышкой `.gitignore`
не действует — следи за этим руками. Сборщик возьмёт содержимое этого файла, зашифрует и вошьёт
в `index.html`. Сам файл на сайт **не выкладывается никогда** — иначе
его открыли бы по прямому адресу в обход пароля.

Проверять локально: `python build.py`, затем открыть `_site/index.html`.

Когда результат устраивает — скопируй всё содержимое `vault.html`
в секрет `VAULT_HTML`. Файл лежит в `.gitignore`, поэтому в публичный
репозиторий его содержимое не попадёт.

Это полноценная HTML-страница: свой `<head>`, свои стили и **рабочие
скрипты**. После входа она разворачивается в отдельном документе внутри
страницы, поэтому ведёт себя как обычный html-файл. Обрывок без тега
`<html>` сборщик сам обернёт в готовую тёмную страницу.

Внутри работают подстановки: `{{VIDEO}}` превращается в плеер из секрета
`VAULT_VIDEO`, `{{TEXT}}` — в текст из `VAULT_TEXT`. Так вёрстка живёт
в файле, а ссылка и текст остаются секретами.

Если после входа виден только чёрный экран — значит показывать нечего.
Сборщик предупреждает об этом строкой «ВНИМАНИЕ: после входа не будет
видно ничего». Чаще всего причина в том, что в файле остались одни
подстановки, а секреты `VAULT_VIDEO` и `VAULT_TEXT` не заданы.

Источники берутся по порядку: секрет `VAULT_HTML` → файл `vault.html`
→ секреты `VAULT_VIDEO`/`VAULT_TEXT`.

**Важно про `RECOVERY_VIDEO`.** Этот экран открывается до ввода пароля,
поэтому его видео обязано быть в открытом виде — иначе браузер не сможет
его загрузить. Секрет прячет ссылку от репозитория и истории коммитов,
но в опубликованной странице её будет видно. Если видео должно быть
тайной — его место в `VAULT_VIDEO`, за паролем.

## Публикация

1. Создай репозиторий и загрузи туда все файлы, сохранив структуру
   (папка `.github/workflows/` обязательна).
2. Добавь секреты из таблицы выше.
3. Settings → Pages → Source: **GitHub Actions**.
4. Сделай push в `main` (или Actions → «Сборка и публикация» → Run workflow).
5. Через пару минут адрес появится во вкладке Actions.

Менять логин, пароль или видео можно прямо в секретах — после этого
запусти workflow заново, страница пересоберётся.

## Локальная проверка

```
cp secrets.local.example.json secrets.local.json   # впиши свои значения
pip install cryptography
python build.py
```

Готовый сайт появится в папке `_site`. Файл `secrets.local.json`
занесён в `.gitignore` и в репозиторий не попадёт.

## О стойкости

Шифрование надёжное, но перебирать будут не его, а пароль: шифроблок
скачивает любой, кто открыл страницу, и подбирать может сколько угодно,
без ограничений на попытки. Короткий пароль или дата подбираются быстро.
Если за входом что-то действительно важное — ставь длинную фразу
из 4–6 несвязанных слов.

И ещё: если ты хоть раз закоммитишь файл с открытым паролем или ссылкой,
он останется в истории git навсегда, даже после замены.

## Атрибуция звука

Фоновый трек — «Dark and Stormy» от Tabletop Audio (tabletopaudio.com),
лицензия Creative Commons Attribution-NonCommercial-NoDerivatives 4.0.
Условия: только некоммерческое использование, без изменений трека и с
указанием автора. Указание вшито комментарием в начале страницы; ID3-теги
внутри mp3 трогать нельзя — там тоже атрибуция.

## Ограничения политики безопасности

В странице стоит Content-Security-Policy. Она разрешает картинки и звук
только со своего сайта, а из внешнего — только плеер youtube-nocookie.com.
Если добавишь в vault.html картинку или шрифт с чужого домена, браузер их
заблокирует: дополни список в теге CSP внутри template.html.
